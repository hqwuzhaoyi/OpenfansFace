# 视频水印核对与归名

本技能在 face-admin-next 项目内维护。先读 [项目经验入口](../../../docs/experiences/README.md)，按需查看 [操作流程](../../../docs/watermark-workflow.md)。真实运行资料统一保存在本项目 `.local/experiences/`；后续更新使用项目内的文件。

把文字证据、人物归属和归档执行分别记录。用户请求扫描时产出名单；已明确请求分类时执行覆盖范围内的归名，沿用应用现有的归档和撤销流程。

## 确定本轮范围

从当前待分类数据源读取稳定视频 ID 和实际路径，包含无脸视频。记录范围、抽样方法、文件大小和高精度修改时间。在已有项目中先读其水印运行文档、worker 和分类接口；对于 face-admin-next，入口是 README 的水印章节及 `docs/watermark-workflow.md`。

确认当前部署与本地代码的关系。存在源码、测试或过往部署记录，不代表新功能已在线。资源有限的媒体主机可只负责只读抽帧，再把 OCR 放到有资源的机器；根据实际资源选择并行度。任务分配应互斥，保留完成标记供恢复。

## 采样与聚合

起点可以是覆盖开头、中段和结尾的 8 个时间点，全帧检测加角落放大；短暂水印需要补采。优先复用项目既有参数，而不是另写一套不一致的默认值。

FFmpeg 成功退出可能没有生成新帧。每次提取前清理该次临时输出，确认新图片存在；同一帧的多个裁剪仅算一票。默认以两个不同时间点重复出现作为候选证据，允许按复查目的单独展示被过滤的原始读数。

保存原始文字、平台线索、位置、时间点、不同帧数、OCR 分数、截图及文件指纹。OCR 分数表达文字读数的把握，不能解释成人物归属概率。文件或识别管线变化时重新判断缓存有效性。

## 从读数到名单

区分作者账号、疑似署名、转载频道或站点、字幕或软件标志。完整平台 URL 和 TG / X / IG 前缀可提供平台线索；保留原文和账号标点，避免模糊合并不同账号。

核对代表性截图中的尾部下划线、数字后缀、大小写、l / 1 等。截断的截图回到原始时间点扩大区域，能读出后再补全。校正记录应包含原读数、校正结果、证据与适用视频；局部短前缀的补全不自动扩展成全库规则。

人物库精确同名是有用线索。已确定属于同一人的账号优先复用已有名字；多个账号同时出现只说明共现。不能确定的多账号关系保留待核对，频道来源不直接当作人物。

输出每个候选账号对应的文件数量与可追溯明细。区分按路径去重与按内容去重，说明同一文件可能出现在多个账号组。分别报告文字检出量、人物候选量、未检出量和读取失败；未经真值标注，不能把文字检出率称为人物分类准确率。

## 执行已有授权的归名

先生成视频到人物的具体计划，单列歧义项，并保存操作前状态。提交前核实当前范围与文件指纹仍匹配扫描证据。通过现有应用接口提交可撤销批次，记录回执及本轮标识。

写请求结果未知时先读回状态，核实已完成部分再继续。检查新增视频及目标人物逐项匹配，原有队列记录未被覆盖，冲突和未检出项仍可复查。撤销应针对本轮视频，避免恢复旧快照而覆盖后来操作。报告清楚是已归名、已加入待归档，还是已移动文件。

历史认可说明方法可复用；新任务的范围和写入操作依据当前授权确定。

## 未检出与交付

未检出可能是无水印、采样遗漏、文字难辨或重复阈值过滤。交付编号、播放地址、原路径、时长和实际采样点；验证地址时说明验证范围，例如读取一个字节不能证明全片可解码。

用户指出出现区间或位置后，在该处补帧、扩大或改变裁剪，并检查单帧读数。纯图形水印需要另外的方法。

把原始结果、人工校正、名单、回执和待复查清单保存到项目的 `.local/experiences/<任务>-<日期或批次>/`，在 `docs/experiences/README.md` 增加入口。完整视频路径、私有截图和机器地址保留在这份 Git 忽略的任务资料中，不写入可共享技能正文。完成时给出项目内交付链接、实际处理数量和仍未解决的项目。
