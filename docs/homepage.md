# 首页与任务进度

首页使用 Cards 方案。`/` 展示库存、全局进度、任务分布和近期记录；`/operations` 是独立处理操作台，负责队列筛选、搜索、重试、优先级和批次操作；`/review` 负责人工确认。统一导航包含明确的“首页”入口，品牌也返回首页。首页图表与任务详情通过阶段参数进入操作台，不再重复呈现整张任务表。

## 组件

`components/beui/` 保存从 BEUI 官方 registry 获取的组件源码和 MIT 许可。首页使用 Card、Digit Swap、Animated Badge、Button、Animated Sidebar、Tabs、Table、Drawer 和 Donut Chart。共享动效配置在 `lib/beui/ease.ts`，沿用项目 easing，缩短状态切换，并处理 reduced motion。

布局在 `components/home/`。统计口径收进可键盘操作的说明按钮，页面不保留原型选择器、演示数据或装饰性说明。

## 数据与入口

- `/api/home/tasks`：处理队列、运行任务、worker 心跳和近期事件。每 3 秒更新；隐藏页面降低频率。查询不依赖当前列表页来判断运行任务。
- `/api/home/metrics`：待分类、归档队列、相似组、人物目录、文件数和磁盘状态。目录遍历限制并发，进程内缓存 60 秒。失败项显示不可用，不填零。
- 自动分析的待确认数指向 `/review`。旧流程候选保留在“识别报告”，指向 `/approvals`，不混加两个队列。
- “在库文件”包含人物归档目录中的非视频文件；“人物目录”不等于独立身份数。磁盘容量按 GiB 显示。
- 不再把报告扫描数量作为 My TG 实时剩余量。

## 进度记录

任务记录写入 `FACES_BASE/jobs/<lane>.json`，原子替换；不改写识别证据或归名决定。字段包括运行 ID、任务类型、状态、阶段、当前文件、已处理量、总量、单位、开始时间、最近进展及心跳。

`maintenance/task_progress.py` 记录文字、人脸和媒体发现进度。人脸与文字按采样帧上报，媒体发现区分账本读取、文件检查和参考更新。百分比只表示当前阶段可量化的工作量，总量未知时不模拟百分比。worker 恢复后的心跳不会把已中断的旧执行标成进行中。

归档请求通过 `lib/runtime-jobs.ts` 上报移动、账本同步和失败恢复阶段。文件移动使用异步的排他路径操作，使进度查询可以继续响应。文件和账本仍按原有流程处理；首页不增加自动归名、自动归档或删除操作。

暂停只停止领取新分析任务，当前阶段继续完成。重试和提高优先级复用处理接口。断线保留最后一次计数并明确标注，完成状态不因心跳过期而变成断线。

媒体清单查询直接在只读 SQLite 连接中执行单条 SELECT，利用 SQLite 的读快照一致性，不把整个 Peach 账本复制进内存。

## 验证与发布

核心测试：`tests/home-model.test.mjs`、`tests/test_task_progress.py`、归档文件测试和隔离处理流程 HTTP 测试。生产数据只做读取验收，写入回归必须使用独立夹具。

生产镜像应在独立构建机生成，再上传到运行服务的主机。不要在内存受限的媒体虚机上并行构建 Next.js 镜像。切换前记录实际线上容器与源码基线、校验人工状态、备份处理数据库并等待当前分析阶段结束。保留旧 Web 和 worker 容器，恢复原有暂停状态。
