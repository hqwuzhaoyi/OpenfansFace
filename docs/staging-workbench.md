# 回收站工作台与 Rust 接口

`/staging` 使用共享工作台外壳，桌面展示暂存概况、文件列表和详情；窄屏在记录下方展开详情。“视频体检”独立显示，保留 `/staging#video-health` 深链接。

界面复用 BEUI / ReUI 工作台按钮、卡片、复选框、搜索、标签页和响应式弹窗。布局参考 ReUI Filespace。只合入页面组合与交互，不恢复旧 Node 文件执行器或 Python 账本代码。

## 原生契约

- `GET /api/staging?offset=...&q=...` 使用 Rust 分页与搜索结果，整体暂存数量/体积与当前匹配数量分开。每页 100 项；“全选本页”只选当前页，“全选搜索结果”遍历服务端匹配页，超过 500 项时要求缩小搜索。切换搜索与分页保留勾选，选择与查看独立。
- `POST /api/staging` 保留原生 `preview`、`apply`、`reconcile` 模式。恢复使用 `restore-files`；永久删除使用 `delete-staged`；清空使用 `clear-staging`。执行提交服务端返回的 `request` 和 `version`。
- 恢复每次核对一个文件。已知来源可选原路径；也可明确指定人物及其相对子目录。原生后端遇到同名冲突会停止，界面不承诺自动改名或批量恢复。
- 永久删除和清空保留不同的确认文字；清空始终预览全量范围，与当前搜索及已选项无关。
- `GET /api/staging?id=...` 查询持久化进度；显式“核对恢复状态”调用原生 `reconcile`。保留已删除、未开始、失败、已回退、需恢复和内容已删除但记录待核对等实际状态。
- 浏览器保存回执入口，刷新后只查询，不自动提交。兼容旧 Rust 页面保存的永久删除计划。服务端始终校验编号、范围和版本。
- 视频播放保留稳定引用及原生健康指纹/material 保护；播放失败仅用核对过的身份报告，不能退回旧的无指纹报告方式。

## 视频体检

直接读取既有 Rust 体检接口；`never_run`、`running`、`skipped`、`interrupted` 和成功结果分别展示。没有成功检查时不能显示为健康或零异常。刷新仅查询结果，运行中每 15 秒读取一次。

## 验证

隔离构建后运行 `tests/http-rust-staging-delete-gateway.py` 验证真实 Rust → Next 网关的暂存、恢复、永久删除、清空、重放、回执与 Range 播放；路由、传输与健康指纹单元测试保护现有边界。

浏览器使用标记夹具验证桌面、390px、键盘、焦点恢复、reduced motion、实际视频播放、跨页/搜索选择、确认与回执查询。真实媒体不作为写入测试对象。
