# Rust 两人物合并隔离验证

本票通过原生 `merge-person` 接入既有共享执行器，Next `/api/persons/manage` 仅按已保存的执行归属转发。界面的两人／多人合并对话框使用 `/api/persons/batch`，该批量入口由 #12 接续；本票没有新增 Node 执行器或改写对话框。

## 实现边界

- 来源与明确保留人物均从现有目录／已保存人物记录解析，拒绝同一人物、别名循环及账本歧义。计划携带来源完整移动清单、目录映射、总字节、真实目标文件预览和两侧相关版本。
- 使用归档的“保留两份”命名规则；保留同名文件、文件／目录碰撞、大小写和 Unicode NFC 冲突、隐藏附件、空目录以及不同名称的硬链接。只为实际视频分配缺失的稳定编号。原来源空目录在核心提交确认后按持久证据清理；晚到内容不被递归删除。
- 元数据沿用现有语义字段及优先级。目标模板、人物资料、手动关联 ID、同键拒绝和队列记录优先；候选合并保留最大分数／支持数和证据并集。待核对资料的 `candidate` 不因合并变为 `reference`。原始 OCR、稳定编号、事件审计、外部资料姓名和独立源／保留／暂存位置不改变。
- Peach 使用观察到的真实 schema 和完整行。按实际文件／目录映射迁移全部来源前缀资产（包含历史和已处置资产），保留关联的角色、来源、附加字段及全部别名的实际主键。目标同键关系优先，来源实体和别名存入目标附加资料。未知占用外键（包括复合外键）、重复来源资产、目标冲突和异常元数据停止操作。
- 共享原生创建意图增加可选别名与附加资料。SQLite 在删除来源实体前分配目标 ID，避免重用刚删除的来源编号；同一事务最终形成可检查及补偿的聚合行快照。没有预测 `MAX(id)+1`，没有额外执行器。
