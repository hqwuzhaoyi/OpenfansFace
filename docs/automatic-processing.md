# 自动分析运行说明

设计约定见 [设计访谈](design/processing-workbench-interview.md)、[ADR 0001](adr/0001-automatic-analysis-with-conditional-face-matching.md) 和 [ADR 0002](adr/0002-separate-processing-state.md)。

## 页面与数据流

处理操作台 `/operations` 管理自动任务；人工确认 `/review` 处理人物归属。首页 `/` 保留库存与全局任务摘要，品牌入口可以返回；五个流程入口来自 `lib/workbench-navigation.ts`。旧待分类、审批及相似组链接兼容到人工确认，并尽量保留视频或组筛选参数。

操作台顶部单独展示当前处理进度，复用 `/api/home/tasks` 的真实阶段记录：当前视频、阶段、已采样帧数、耗时及最近更新时间。每 5 秒刷新，只有已知总量时显示当前阶段百分比；不推算全库完成时间。列表的阶段、批次和搜索筛选不影响顶部进度。请求超时、心跳中断或状态过期时明确提示连接问题，保留上次结果。

新视频以现有媒体库账本为来源，不遍历整块 NAS。`/api/processing/inventory` 在 Peach 内用 SQLite backup API 生成一致内存视图，包含已提交的 WAL 数据，再返回视频资产。处置为 trash / vanished 的条目、creators、回收站、已归名队列和已归档记录都按当前范围排除；不沿用旧扫描器的 60 秒限制。

发现线程每 5 分钟检查一次，登记与人脸分析分开。任务按人工优先级、新增视频、历史存量排序。全局暂停停止领取新的模型阶段，已开始的阶段会完成，轻量发现仍可更新队列。批次按发现轮次记录，各视频独立进入人工确认，不等待整批结束。

领取任务前先检查媒体根目录是否可读。整盘挂载异常时保留任务，记录一次挂载异常事件；恢复后自动继续。若模型阶段中途遇到同样的整盘故障，将本次尝试退回，避免全库任务逐个耗尽重试次数。挂载正常时的单文件读取或模型错误仍按首次执行加两次重试处理。该检查针对根目录不可读，不把个别文件错误当作整盘故障。

文字阶段复用有效 OCR 缓存，并匹配文件名、文件夹线索。只有命中已确认的账号映射且无已知冲突时才跳过人脸；来源水印不作为人物建议。人脸阶段使用 detection / recognition 模块提取特征，参照已有明确代表脸和已确认视频的相干参考形成候选；未匹配已知人物的相似人脸可形成未命名组，仍须逐视频人工核对。

## 部署

Web 继续使用项目 Dockerfile。协调器依赖已有的水印基础镜像，以及 InsightFace / ONNX Runtime；版本记录在 `maintenance/*-requirements.txt`。构建命令：

```sh
docker build -f maintenance/Dockerfile.watermarks -t face-watermarks:v1 .
docker build -f maintenance/Dockerfile.processing -t face-processing:local .
```

启动协调器时，挂载与 Web 相同的 `FACES_BASE`、同路径的只读媒体目录、可读取的 `buffalo_l` 模型目录及 PaddleOCR 模型缓存。实际部署将 CPU 限制为 1 核、内存上限设为 1.5 GiB；正式使用前以本机模型实测资源为准。

```sh
docker run -d --name face-processing --restart unless-stopped \
  --network host --cpus 1 --memory 1536m --pids-limit 256 \
  -e FACES_BASE=/data/base -e MEDIA2_ROOT=/mnt/media2 \
  -e FACE_ADMIN_URL=http://127.0.0.1:8919 \
  -e WATERMARK_CPU_THREADS=1 -e OMP_NUM_THREADS=1 -e OPENBLAS_NUM_THREADS=1 \
  -v /YOUR/face-data:/data/base \
  -v /YOUR/media:/mnt/media2:ro \
  -v /YOUR/insightface-cache:/root/.insightface:ro \
  -v face-watermark-models:/root/.paddlex \
  face-processing:local
```

Web 地址必须从协调器容器内可达。启动自动协调器前停止独立 `face-watermarks` worker，让水印结果只有一个写入者。OS 文件锁阻止两个协调器同时领取任务。上线预览可先把 `settings.paused` 设为 true，验证发现、模型和接口，再通过操作台恢复自动分析。

## 运行资料

| 位置（相对 FACES_BASE） | 用途 |
| --- | --- |
| `processing/processing.db` | 任务阶段、重试、优先级、暂缓、备注与事件 |
| `processing/heartbeat.json` | 协调器心跳及当前文字管线版本 |
| `processing/references.npz` | 版本化人物参考 |
| `processing/faces/` | 按视频保存、绑定路径/大小/修改时间/模型版本的特征 |
| `processing/thumbs/` | 每帧每张脸的独立截图 |
| `watermarks/results.json`、`watermarks/evidence/` | 兼容原水印证据缓存 |
| `jobs/` | 逐阶段实际进度，供任务摘要使用 |

旧人脸特征不冒充已通过新指纹校验的缓存。既有人物校准接口仍针对旧库，新流水线结果由人工确认页呈现。候选相似度不是人物正确率；文件变化、阶段异常或媒体可读数量骤降时，系统保留可追溯状态而不伪装分析成功。

## 人工处理

默认按候选人物分组，冲突和无候选独立筛选。每个文件只出现一次；同片多个候选不会变成多个可重复归档的文件。组内默认不勾选，全选只作用于当前页。无候选可以手选或新建人物，技术失败可从操作台接管；其他出镜人物通过备注记录。

归名提交会再次核对文件指纹，只改本次选中项。旧队列条目不会因新增归名而补写来源字段。可选保存共同作者账号的映射；原始截断读数不能无条件推广成全库规则。归名后进入待归档，备注随记录保留；撤销会恢复可用的人工确认状态。

## 本次验收

已验证状态机与接口回归，包括暂停、两次重试上限、文件变化、候选去重、备注与暂缓、队列保留和撤销。真实容器跑通了 OCR → 人脸采样 → 就绪；真实待处理视频试跑检出 3 张脸，因两个候选进入冲突核对，没有自动归名。

首次发现登记了 962 个此前未登记的视频，形成 4,125 个可处理任务；这是当时的快照，后续以实时页面为准。最终容器检查覆盖原生 SQLite、媒体 Range 读取、归名与撤销；页面检查还拦截了操作台被错误替换成总览的情况，回退后保留首页并恢复独立操作台。

部署回执、测试记录、构建快照和回滚信息保存在项目 `.local/experiences/processing-release/`。恢复旧协调器容器时，应同时核对其 Web 服务地址；预览地址不是正式服务地址。回滚应用版本不应把旧队列备份覆盖到用户后续操作上。

## 连续工作区

处理操作台的实时进度保持在顶部状态条，阶段使用共享 BEUI Tabs；文件队列占据主区域，运行记录默认折叠。点击任务查看右侧详情，窄屏使用底部面板；搜索与发现批次组合在 ReUI Input Group 中，筛选不影响实时进度。

人工确认桌面采用确认组、视频列表、视频与归名详情三栏。搜索和原文件夹只筛选当前组视频，不隐式切换确认组。宽度低于 1200px 时，视频与归名使用同一个响应式面板；手机将确认组与文件夹筛选收进搜索入口。

- 点击行查看证据，复选框独立勾选。选择按确认组与暂缓状态分开保存，搜索、翻页及查看其他组不会清空当前挂载页面的选择。
- 全选仍仅作用于当前页。有选择时显示底部批量操作栏，并明确不在当前页或被筛选隐藏的已选数量。
- “核对所选”显示完整文件名单和路径，再选择人物并提交；不同确认组不会自动混在同一批次。
- 提交保留勾选时的文件指纹，服务端在写锁内复核文件、就绪状态，以及可选的 `review_group` 分组和暂缓状态。某项已变更时整批拒绝，保留选择供重新核对。
- 成功后按实际回执更新并提供撤销与待归档入口；失败保留选择与输入。面板关闭恢复触发点焦点和列表滚动位置。
- 高频筛选使用 Tabs 的 `instant` 模式。面板只在打开时确定动效；键盘及 reduced-motion 立即显示，后续输入方式变化不重播入场。

## 内部控件与草稿

两页的动作按钮与证据卡片使用 BEUI，输入、搜索和下拉筛选使用共享 ReUI/Radix 组合。筛选的弹出选项通过 Portal 呈现，避免在滚动面板中被裁切；键盘选择、关闭后的焦点和触控尺寸共用同一规则。

- 人物选择与人物库共用 Unicode、别名和多词匹配。已有名字从列表明确选取，新名字通过“新建人物”输入，不把搜索文字自动当作归名结果。
- 归名人物和账号规则按确认组保存，未保存备注按视频保存；在当前工作区切换视频、分组、证据或对照时保留草稿。改变本次勾选范围后重置账号规则，再核对共同证据。
- 对照视频在当前详情面板内展示，不叠加播放器弹窗。返回时恢复原来的选择、人物搜索和详情滚动位置；切换媒体时停止旧播放器，并记住本次浏览期间的播放位置。
- “仅作来源”先展示影响范围，再确认保存；仅在成功回执后清空选择并刷新建议。失败保留操作内容，错误同时显示在详情内。
- 两页共用 URL 查询状态，前进/后退恢复搜索、筛选与页码；列表滚动位置按页面与筛选组合保存。重新打开页面会重新读取实时数据，不把旧界面快照作为提交依据。

组件来源及许可证见 `components/beui/LICENSE`、`components/ui/SHADCN-LICENSE.md` 和组件文件头。内部业务组合位于 `components/workbench/inner.tsx`；它复用已有交互原语，不实现另一套选择或弹窗机制。

## 确认列表证据摘要

`/review` 的每条记录组合现有 BEUI Card、Checkbox、Button 与共享路径控件，默认呈现视频截图、路径、水印原文和代表性水印截图、候选人物及其逐条依据。点击文件名、截图或水印证据进入原详情；复制路径与勾选互不影响。

摘要直接读取本轮分析记录：明确区分命中已确认账号映射、未确认账号文字、频道线索、路径命中与人脸相似度。相似度保持原始分值，不转成人物正确率；没有依据时显示未记录，冲突与未完成分析不被折叠成单一确定结论。列表仍需人工确认后进入待归档，不自动归名或移动文件。

视频截图复用合并预览的懒加载封面方式，优先读取相关水印的实际时间点；短视频按真实时长约束。浏览器最多同时解码两个截图请求，只在内存中按路径、文件指纹、采样点缓存，滚出视口或卸载时取消未完成请求，不播放声音，不写入媒体库。无法解码时明确显示截图暂不可用。封面与水印图沿用隐私遮挡。


## 归档目标账本冲突与本轮回退

归档预览会逐项标记已经存在目标 Peach 账本记录的普通归档项，显示无效状态、原因和目标路径。其他检查通过的项仍可明确勾选提交；不会自动替用户选择、重试或重跑整批。已确认的重复件暂存沿用原有 canonical 记录与完整内容校验，不把其合法目标记录当作普通归档冲突。

文件发布后若出现新的目标索引，正常账本提交仍然严格拒绝。仅在归档操作具有签名、原冻结 delta 完全一致的 `prepared`／`cancelled` 回执，且原资产、关联和人物作用域仍保持提交前状态时，才允许取消专用核对。差异必须仅为原先为空的本次普通目标路径新增一条索引行：原 location、文件名、体积匹配；只含已知索引字段，手动字段为 NULL、播放次数与 mutation revision 为零；无任何声明外键或按大小写无关列名识别的 `asset_id`／`*_asset_id` 语义引用。仅实际虚拟 FTS5 表 `asset_search` 的派生记录不算业务引用，普通同名或同前缀表照常核对。未知资产字段、复数引用格式、多条目标记录、手动资料、关联或作用域变化均保留恢复状态。该核对不识别写入者身份，也不用于放宽正常提交。

取消决定在短 SQLite 事务中保存；外部资产及其关联不删除、不合并、不改名、不修改 ID。事务结束后才通过已有文件身份和文档 CAS 机制回退本次文件与队列，过程中及结束时重新核对外部索引。回执分别报告 `own_changes_rolled_back` 和 `external_index_conflicts`，归档仍为失败，旧操作不提供直接重试。外部索引仍可能指向已经回退的目标路径，需要另行核对后刷新预览；这不表示整个 Peach 账本已恢复一致，也不表示归档成功。同一操作编号的重复请求和重启沿用持久化取消／回退决定。

**边界：更早的“文件已发布、但最终成功子集尚未建立 Peach 回执”窗口仍可能进入恢复状态。** 缺失或被删除的回执不当作未提交证明；已提交回执、原记录变化、文件身份或 NFS 结果不确定也不走此例外。本改动不解决所有扫描竞争，不暂停 Peach、不持有跨 NFS 的长 SQL 事务、不引入目标行合并、身份分配或跨服务保留协议。现有外部冲突记录和生产待归档队列不会被自动处理。

### NFS 新目录兼容

部分 NFS 挂载不支持 `RENAME_NOREPLACE` 发布新目录，会返回 EINVAL。
原生执行器仅在明确的“不支持”错误时改用原子 mkdir；已有目录、文件或符号链接仍会令创建失败，不使用会覆盖目标的普通 rename。
兼容创建的最终目录只记录观察身份，不声称有可回收的独占所有权；失败回退时保留该目录（可能为空），只清理已证明归属的临时目录。未确认的创建结果不会在重启后被自动接管，其他 I/O 不确定性继续保留恢复保护。
