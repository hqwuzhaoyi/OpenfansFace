# 处理操作台与统一人工确认：设计访谈

状态：方案已确认并完成首版上线。三轮选择均得到用户确认，自动分析与统一人工确认已接入真实服务。

## 用户提出的方向

- 评估合并“待分类”和“识别待确认”。
- 先利用水印和文件夹名称，再分析视频人脸相似度，最后人工确认。
- 参考 ReUI SaaS 模板，选择合适的交互方式。

术语见根目录 [CONTEXT.md](../../CONTEXT.md)。项目经验继续从 [经验入口](../experiences/README.md) 查找。

## 已核实的现状

- `lib/unclassified.ts` 展示尚未归名、当前可处理的视频总集，按实际路径去重。
- `app/api/claims/pending/route.ts` 展示人脸相似度在 `[0.50, 0.58)` 的未处理候选行，是总集的一个视图；目前并未按视频或路径统一去重。
- 一个视频可以存在多个候选人物，而审批决定按视频 ID 保存。合并入口需要以视频为主记录、候选为集合，不能直接拼接两份列表。
- `identify_faces.py` 已利用部分目录名称建立人物模板，并有可选的文件名增强；这与新的“从待处理目录提取文字线索”不是同一个阶段。
- 水印 worker 与人脸识别管线尚无统一阶段编排。人脸检测和特征生产的一部分位于仓库外，不能在界面上假定已有逐视频可控任务。
- 确认人物与实际归档已分离，多个入口最终写入同一待归档队列；这个边界已有撤销与归档校验支撑。

- [Filespace](https://reui.io/template/filespace-drive)：官方提供文件树、列表与网格、预览、多选和批量操作。已查看在线文件列表。可借鉴人工核对时的列表、预览与批量选择。

## 决策树：第一轮（已确认）

用户回复：“按照建议，除了 q3 是 b”。

1. **人脸分析覆盖范围**：每个视频都必须经过人脸分析，还是已有明确文字线索的可进入人工确认、其余按需补人脸？
   - 已确认：文字线索先做，人脸按需补充。水印命中已确认账号映射且无冲突的文件可直接进入人工确认；没有明确候选或有冲突的补做人脸分析。
   - 后续分支：触发人脸分析的条件、是否等待全部任务完成、无脸或失败的处理。
2. **人工核对单位**：默认按候选人物聚合、按原文件夹逐批，还是逐视频确认？
   - 已确认：默认按候选人物分组，组内逐视频核对、勾选后批量归名；保留原文件夹筛选，证据冲突和无候选有独立筛选。
   - 后续分支：批量选择规则、多候选冲突、多人视频、无候选视频的操作。
3. **任务启动方式**：新视频自动进入分析，还是先由用户选择范围并启动一批？
   - 已确认：选择 B，新视频发现后自动启动分析并接续必要阶段，无须逐批点击启动。自动分析仍然生成候选，由人工确认人物归属。
   - 后续分支：扫描范围、并发与资源限制、暂停和重试、后台自动发现。

自动编排与按需人脸的取舍记录于 [ADR 0001](../adr/0001-automatic-analysis-with-conditional-face-matching.md)。

## 第二轮（已确认）

用户回复“可以”，接受 Q4–Q8 的建议：

4. **启动时的存量**：全部接管现有待分类存量和后续新增，新视频优先、存量后台补齐，复用有效结果，跳过已归档和回收站。
5. **文件夹名的信任程度**：目录与文件名先作为辅助线索；跳过人脸仍要求已确认账号映射命中且无冲突。仅目录或文件名命中姓名仍补做人脸分析。
6. **无结果及失败出口**：无候选、证据冲突进入人工确认的相应筛选；技术失败在首次尝试之外自动重试两次，仍失败进入操作台异常列表，允许人工接管。未检出不触发这类技术失败重试。
7. **多人视频的归属**：本期仍选择一个主归属人物，其他出镜人物用备注或标记保留，避免复制同一视频到多个目录。多账号共现不自动证明同一人物别名。
8. **确认后的归档边界**：保留独立待归档步骤，人工确认人物后批量检查目标路径，再执行文件整理。

## 最后一轮（已确认）

9. **自动发现与运行策略**：已确认以现有媒体库已收录的视频为发现范围，每 5 分钟增量检查；全天低并发运行，新视频优先，提供全局暂停。未纳入媒体库的磁盘文件不默认全盘搜索。具体并发数依运行资源验证后配置。
10. **处理操作台的默认视图**：已确认采用 Pulse 的状态概览与任务表思路；展示排队、文字线索、人脸分析、待人工确认、异常的数量和进度，批次可展开，提供暂停、重试、优先处理。状态由实际任务推进，不用拖拽修改阶段。归名动作集中到人工确认。
11. **人工确认的工作布局**：已确认参考 Filespace 的浏览与多选，桌面左侧候选人物组、中间视频列表、右侧预览和证据；手机使用列表与全屏核对。默认不勾选，批量勾选限当前页，确认完成后继续下一组；无候选仍可手选或新建人物、暂时跳过。

已确认的流程导航为：处理操作台、人工确认、人物库、待归档、回收站。现有待分类与识别待确认合并到人工确认；旧入口、历史来源和撤销返回链接做兼容。系统按单个视频的就绪状态逐步供人工核对，无须等待整批全部完成；任务阶段未完成或失败不能显示成分析成功。

## 自动发现的补充事实

当前 Web 读取已登记的视频，不独立发现磁盘上的全新文件；现有水印任务也从这个范围选取。远端保留的 `scan_faces.py` 在同一进程中先从账本快照登记视频，再启动人脸分析；静态脚本中的目录和时长过滤不应直接当作新流程的需求。

这些远端脚本是否仍为实际运行入口、PC/WSL 是否采用不同版本、Peach 当前发现周期以及外部定时触发方式，尚未完整核实。自动发现的数据源、范围和调度策略仍需据实际接入确定，不能声称当前已经支持“放入目录就自动全流程分析”。
