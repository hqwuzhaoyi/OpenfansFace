# 关联账号资料

人物详情页显示「女菩萨」公开 X 账号目录的匹配资料。在人物选择器中打开“看对照”，也可查看该人物的账号资料。紧凑人物选择器仅在打开弹窗后查询，避免一次请求全部人物。

## 匹配规则

- 已确认的 X 水印账号规则按完整账号匹配，忽略大小写，保留下划线与数字后缀。
- 人物名与账号字样一致但没有平台信息时，显示“待核对平台”。
- 人物名与外部昵称完全一致时，显示“同昵称 · 待核对”；重名记录全部保留。
- 组合人物名按空格、括号、竖线、逗号等明确分隔取名称片段，用完整片段匹配外部昵称或账号。例如 `HongKongDoll 玩偶姐姐` 可按昵称片段 `HongKongDoll` 找到 `@HongKong_Doll`，显示“名称片段一致 · 待核对”。精确匹配层不使用任意子串，也不删除账号下划线来凑匹配。
- Telegram、Instagram、OnlyFans 等平台不按同名映射到 X；来源规则不建立人物关联。
- 资料只供核对，不修改人物名、账号规则、视频归属或归档队列。

## 接口与缓存

`GET /api/persons/external?name=...` 查询人物，合并精确匹配、已核对资料与模糊候选。`GET /api/persons/external?q=...` 使用 2–100 字的自定义查询词检索，人物页的搜索框使用该模式；返回原查询可恢复人物资料。

`GET /api/persons/external?token=...&platform=X` 仍按完整水印账号精确查询（平台也支持 `unknown`）。三个查询参数互斥。响应的 `match_count` 是候选总数，`matches` 最多返回 20 条，已确认规则和已核对资料优先。

## 模糊候选

- 展开组合名字、`@账号`、中英文连写、括号别名、`#` 前缀及明确的采集编号。
- 服务端使用 OpenCC 的繁转简词典和 Unicode NFKC 统一字形；昵称中的表情、空格和装饰标点只用于搜索比较，原昵称及账号保持原样。
- 检索昵称中的完整片段，以及简介明确提及的账号、平台链接或较长名称。简介可能包含推广或转载来源，结果始终标为待核对。
- 账号支持部分查询；短查询只查前缀，长度不少于 6 时可查内部片段或一处拼写差异。拼写候选不跨数字序列，完整水印匹配仍保留下划线和数字尾缀。
- 过滤“姐姐”“Love”“DOM”等通用拆分词，不用两个汉字匹配任意简介，也不把 `rio` 命中到 `curiosity` 内部。
- 人工核对状态与已确认 X 规则优先，模糊结果不会升级它们。搜索框只查询资料，不保存当前人物关联或改动归名。

候选按匹配类型和文本相关性排序；排序数值仅供内部使用，不表示身份概率。功能限于目录中的文字资料，不做跨语言姓名翻译、图像识别或全网搜索。

## 数据来源

服务端读取 `https://img.boomboom.nyc.mn/data/archive.json`，在本地匹配，不向外站发送本地人物名、视频路径或截图。页面保留 `https://nv-pu-sa.pages.dev/` 来源链接、匹配依据、来源更新时间和缓存获取时间。

缓存位于 `FACES_BASE/external-profiles/nv-pu-sa.json`，有效期 24 小时，到期后下次访问时更新。并发请求合并；请求超时或数据无效时保留旧缓存并显示提示，失败后等待一分钟再重试。首次获取失败返回 503，不显示成“无匹配”。资料接口独立加载，不阻塞视频列表。

账号规则从已有的 `FACES_BASE/watermarks/mappings.json` 只读加载；没有水印功能或规则文件时仍可按人物名查询。

## 逐条核对的参考资料

逐条检索结果保存于私有运行文件 `FACES_BASE/external-profiles/reviewed-links.json`，不把本地人物清单写进代码仓库。人物页将这份结果与自动匹配合并；账号水印的直接查询仍只采用原来的精确匹配。

文件格式为 `{ "version": 1, "source": "nv-pu-sa", "links": [...] }`。每条包含 `person`、`profile_id`、`handle`、`confidence`、`evidence`、`reviewed_at`。`confidence` 为 `reference` 时显示“已核对文字线索”，为 `candidate` 时显示“疑似关联 · 待核对”。两者都不代表已确认视频归属。

同一人物可以保留多个候选。参考资料绑定站内稳定 ID 和核对时的账号；账号被重新分配、改名或资料被移除时，不沿用旧关联。既有已确认 X 规则优先，参考资料不写入水印规则、归名队列或人物合并记录。

后续只更新这份运行文件即可更新参考资料，无需重新构建镜像。更新前备份原文件，按人物与资料 ID 合并，原子替换后从接口读回核对。
