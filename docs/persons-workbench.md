# 人物目录工作台

采用已选定的“目录”布局，正式入口为 `/persons`，人物深链接为 `/persons/<姓名>`。
原型选择器、演示人物、样片及另外两版布局已移除。

## 页面与业务

- 左栏合并识别报告、手动人物、归档队列与 `creators` 实际人物目录。每个人物显示视频数量与文件总体积；小徽标单独表示待归档数量。支持按姓名/别名搜索，按最近使用、姓名、视频数或体积排序。
- 中栏读取人物目录实际文件，包含没有识别记录的视频；子目录按真实相对路径生成，没有子目录时只显示“全部视频”。不跟随符号链接。
- “已有视频”和“待归档”分开。待归档按人物筛选，显示原路径、目标路径及阻碍归档的原因。
- 右栏合并识别报告、人脸候选记录和已确认账号映射。展示完整文件路径，支持复制、播放和展开证据。
- 相似度、脸数与水印时间点仅在源记录存在时显示。过期水印指纹、来源标记、已归档和已入队的视频不生成候选。
- “不是此人”保存人物与视频的拒绝关系，绑定文件指纹；可撤销。文件变化后旧拒绝不自动应用。“稍后”仅改变当前浏览顺序。
- 确认归名调用现有队列接口；执行归档只提交明确选中且检查通过的任务，继续使用现有预览版本和二次确认。
- 文件卡片支持重命名、移动、删除；已有视频支持勾选后批量移动和删除。人物标题旁可重命名整个人物。所有操作先预览路径与范围，再确认执行。
- 删除将文件移入全局暂存区，保留内容；不新增人物回收站。移动支持另一个人物或其子文件夹，目标同名时停止，不自动覆盖。

## 接口

| 路径 | 用途 |
| --- | --- |
| `GET /api/persons/library` | 人物目录与待归档计数 |
| `GET /api/persons/library?stats=1` | 所有人物目录的视频数量与总体积；`refresh=1` 强制刷新 |
| `GET /api/persons/library?name=...` | 实际文件、子目录、推荐及证据 |
| `POST /api/persons/recommendations` | 按人物拒绝推荐 |
| `DELETE /api/persons/recommendations` | 用对应操作 ID 撤销拒绝 |
| `GET/POST/DELETE /api/persons/accounts` | 查看、手动关联和解除公开账号资料 |
| `POST /api/persons/manage` | `mode=preview/apply`；文件改名、批量移动/删除、人物改名与合并 |
| `/api/plan/queue` | 复用归名与撤销 |
| `/api/plan/preview`、`/api/plan/apply` | 复用路径校验与归档 |

拒绝记录保存在 `FACES_BASE/person-rejections.json`。本文件属于运行数据，不进入版本管理。

## 外部账号资料

人物页自动查询「女菩萨」公开 X 账号目录，人工确认页的 X / 未知平台账号水印旁也可查看匹配资料。展示昵称、简介、关注者数、X 主页、匹配依据和来源更新时间。

- 已确认的 X 账号人物规则按完整账号匹配，忽略 X 用户名大小写，保留下划线和数字后缀。
- 未注明平台的账号字样，以及人物名与外部昵称完全相同的记录，仅显示待核对资料。同昵称多条记录全部保留，不选取其中一条冒充已确认关联。
- Telegram、Instagram、OnlyFans 等平台的账号不会按同名映射到 X；不模糊补全 OCR、不使用头像做身份判断。
- 外部资料不写入人物归名规则，不影响推荐评分、归档队列或文件。自动匹配随现有人物名及已确认规则计算；撤销规则后不再标注该规则。手动关联独立保存，需通过“解除关联”移除。

人物页无账号结果时不占位置，有结果时显示默认折叠的“账号资料 + 数量”入口，旁边是管理关联图标。BEUI Button、Digit Swap 与 Card 展示资料；展开内容用 160ms transform / opacity 反馈，键盘及减少动态效果即时响应。卡片保留账号链接、简介、关注者数量、关联状态与待核对依据，省去重复标题和说明。退出中的内容立即 inert；同一人物刷新时保持展开状态。

人物列表每行提供“关联账号”按钮，点击可管理该人物的已关联账号并搜索新账号，不会切换当前正在浏览的视频目录。搜索支持昵称、账号、别名、繁简体及相近字样；显式搜索可用一个汉字查昵称。结果仍标明匹配依据，选中后才提交确认，不要求本地人物名与外部昵称一致。

手动关系保存于 `FACES_BASE/external-profiles/manual-links.json`，绑定稳定的公开账号 ID，并保存关联时的资料快照。支持一个人物关联多个账号、解除关联和重复提交去重；只操作指定人物的关系，不修改视频归名、水印规则或归档队列。公开资料不可用时仍能管理已保存的关系。人物改名会迁移手动关系与已核对线索，但不会改写外部账号的原昵称和简介。

`GET /api/persons/external?name=...` 查询人物资料；`GET /api/persons/external?token=...&platform=X` 查询水印账号（平台也可为 `unknown`）。该接口独立于人物库读取，外站故障不会阻塞视频列表。

服务端从 `https://img.boomboom.nyc.mn/data/archive.json` 读取目录，在本地匹配，不向外站发送本地人物名、路径、截图或视频。缓存位于 `FACES_BASE/external-profiles/nv-pu-sa.json`，24 小时后下次访问时更新；请求超时、无效数据或更新失败时保留旧缓存并显示提示。无缓存且读取失败返回 503，不把失败显示成“没有匹配”。页面保留 `https://nv-pu-sa.pages.dev/` 来源链接。

## 文件操作与一致性

单项操作为 `rename-file`、`move-files`、`delete-files`、`rename-person`、`merge-person`、`delete-person`。单次文件操作最多 500 个；人物改名会保留整个目录的文件、附属资料与空子目录，不与现有人物合并。文件改名保留扩展名。

- 预览绑定源文件指纹、目标路径、相关 JSON / SQLite 数据及 Peach 账本版本；执行前重新校验。
- 文件移动不覆盖目标；相同操作编号和版本重复提交返回原成功回执。
- 同步 `faces.db` 的实际路径、归档历史、队列、人物名单、模板选择、水印人物映射和按人物拒绝记录。处理任务数据中的人物名及文件路径也会同步；正在运行的旧人脸任务不覆盖改名结果。
- 有记录的视频保留旧 ID。未扫描文件在首次操作时登记稳定 ID，通过 `video-path-overrides.json` 保持后续路径引用。旧人物名通过 `person-renames.json` 解析到新名，允许再改回原名。
- 原始 OCR 文字、历史稳定 ID 和操作审计保留原值；这些属于证据或标识，不应为了清除旧字样而篡改。
- 删除后的路径位于 `.face-cleanup-staging/person-deletions/<操作编号>/`，待分类与归名入口排除暂存路径。

操作日志、原 JSON 备份及 SQLite 受影响记录快照保存在 `FACES_BASE/person-operations/<编号>/`。Peach 使用 `_face_admin_person_ops` 操作回执：先保留编号，提交后记录状态，结果查询会阻止尚未开始的迟到提交。普通失败会回退文件和本地记录；若远端结果无法确定或回退条件已被外部操作改变，会保留日志和写锁，明确返回需要核对恢复，不能盲目清锁或重复执行。

默认通过现有 Docker Peach 容器更新账本。提供 `PEACH_LEDGER_PATH` 时使用直接挂载的可写账本；此文件必须已存在。可选 `PYTHON_BIN` 指定本地 Python，容器模式仍使用容器内 Python。

`tests/http-person-file-operations.py` 在独立夹具上实际执行四类操作，覆盖路径穿越、扩展名、目标冲突、过期源文件、未扫描文件、稳定播放链接、跨人物关联、人物改名及改回、空目录、账本故障回退、丢失回执和迟到请求阻断。真实媒体库不作为写入测试对象。

`tests/person-accounts.test.mjs` 和账号搜索测试验证手动关系、稳定 ID、重复记录保护与显式短关键词；`tests/http-person-accounts.py` 验证关联/解除、人物改名迁移、外部昵称保留和不改动归档/水印数据。

## 人物列表统计与合并

名单先加载，统计由独立请求补齐。统计递归读取实际视频文件，排除符号链接、隐藏文件和非视频附属文件；体积是视频文件大小之和，不是去重后的物理磁盘块占用。服务端单轮最多并发读取 4 个人物目录，缓存 60 秒；刷新按钮强制更新，归档和文件操作成功或回退后使缓存失效。无法读取的目录显示“统计不可用”，不会按 0 参与数量/体积排序。

人物搜索采用 ReUI `c-input-group-37` 的 Input Group 组合（底层为 shadcn/ui Input Group，MIT），搜索、清空与排序图标放在同一边框内。有输入时显示清空按钮，清空后焦点留在输入框；Escape 可清空，但不会打断中文输入法。排序入口是输入框末端的图标按钮。菜单将最近使用、名称、视频数、体积与升降序分开，当前项以勾选标记；支持键盘与关闭后焦点恢复。

人物列表每行有独立复选框，勾选与查看分开。列表底部固定显示选中后的操作栏，未选中时隐藏删除和合并按钮：选择至少一人可删除，至少两人可合并；合并目标必须从已选人物中指定。搜索、排序和查看其他人物均保留勾选；全选仅作用于当前搜索结果，底部操作栏显示所有已选数量并可清空。单次最多 50 人。`merge-person` 复用文件操作的预览、版本校验、日志和补偿流程。

- 迁移来源目录全部文件与空子目录。目录同名时合并结构；文件同名或文件/目录冲突时为来源项目生成保留名，在预览中列明，不覆盖、不自动按内容去重。
- 来源人物从名单消失，旧名字作为目标别名继续可搜，旧深链接继续指向目标。
- 合并识别条目、待归档、人物资料、水印映射、手动账号关联、已核对文字线索和拒绝记录。同视频/账号重复项去重，保留目标既有记录；文字线索有不确定性时仍保留待核对状态。
- 目标已有模板选择保留，来源设置及原始资料留在操作备份中。外部账号的原昵称和简介不随本地人物合并被改写。
- Peach 迁移来源实体的资产关系及别名，重复关系保留目标记录。来源附加资料并入目标的合并记录；原实体在关系迁移完成后移除。有未知外键关联时停止，避免丢失未支持的数据。
- 合并后的分析候选按同一人物合并证据，后台参考缓存安排刷新，无关任务保持不变。

`tests/person-list-model.test.mjs` 覆盖别名搜索、数值排序和未知统计置后；`tests/http-person-merge.py` 覆盖实际目录统计、同名保留、空目录、资料迁移，以及账本提交前/后失败时的完整回退。

## 人物批量操作

`POST /api/persons/batch` 的 `preview` 接收 `{action:"merge"|"delete",people:string[],target?:string}`，返回服务端保存的预览编号和版本；`apply` 仅提交该编号与版本。先在共享写锁内校验所有预览，再依次处理每个人物。因前一项可能改变目标目录冲突及公共资料，下一项重新规划并验证来源文件指纹；同名文件仍保留两份，最终文件路径以单项操作日志为准。

批量不是跨人物的单一事务：某个人物失败时回退该项并停止，返回已完成和未完成名单。完成的单项不重复执行，同批次重试返回既有结果。进程中断而批次仍为运行状态时阻止盲目重试；Peach 状态未知或补偿失败时保留恢复写锁。

`delete-person` 将人物整个目录（含附属文件和空目录）移动到全局暂存区，撤回其待归档任务、清除活动账号关联和识别映射。`people-deleted.json` 记录移除标记，避免历史归档和旧报告使人物重新出现；原始历史和 Peach 人物关联保留供审计，账本文件路径更新为暂存路径。之后通过人工归名显式创建同名人物时清除该名称标记。删除操作的原始资料保存在每项操作备份中。

`tests/http-person-batch.py` 在独立 `8923` 夹具验证选项约束、全批次过期拦截、多来源同名、部分完成、幂等回执、删除故障回退、空人物删除以及历史记录不使人物重新出现。

## BEUI 与交互反馈

人物页按钮、人物和视频复选框、计数使用仓库内 BEUI Button / Checkbox / Digit Swap。复选框采用仅透明度与轻微缩放的克制样式，保留原生键盘操作语义、部分选中状态和独立勾选；频繁搜索、排序、列表查看保持即时更新。

Motion 用于选择数量更新、确认步骤切换及操作提示的进入/退出；按钮按压反馈采用 CSS transform。共享 `EASE_OUT` / `--ease-out-ui`，时长 160–180ms。弹窗沿用 Radix 的焦点约束并在关闭时恢复至触发按钮。键盘操作和系统减少动态效果会切换为即时反馈；退出中的提示立刻 inert，避免不可见按钮继续接收操作。布局尺寸不参与动画。

## 合并视频预览与执行反馈

合并弹窗在选择和确认阶段展示每个人物的真实视频卡片。`/api/persons/library?preview=1&name=...&offset=0` 返回视频总数、总体积和每页 4 条视频数据，跳过推荐推断；客户端最多并发读取 3 个人物，初始每人展示 2 个视频，支持展开和继续分页。已有缩略图优先使用，否则进入视口后读取视频首帧；点击后在弹窗内用原视频地址直接播放，展示完整路径。空目录和读取失败分别显示，不用示例图替代真实数据。

合并方向图保留各来源与目标人物。确认后通过 `GET /api/persons/batch?id=...` 读取服务端日志中的当前人物和已完成项目，进度按完成回执更新。每个完成项目触发 240ms 的头像合入动画，进度条只反映实际已完成数；键盘和减少动态效果模式不播放位移动画。失败不会被绘制成全部完成。

成功后保留结果弹窗，重新读取目标视频数量；点击“查看合并后的视频”关闭弹窗并进入目标人物的视频区。视频播放在执行前停止，避免继续读取已搬移的来源路径。

人物列表的账号按钮直接显示手动关联状态：绿色链条图标与账号数量，灰色断链图标表示未关联；悬停提示和无障碍名称保留完整状态。`libraryPeople()` 一次读取本地关联记录，按当前人物名归一并以账号 ID 去重，不请求外部资料站；姓名候选和文字线索不计入。读取失败返回未知状态，不当作零条。关联或解除成功后刷新人物列表，保留当前勾选和查看对象。


## 归档可靠性与目录权限（2026-11-07）

归档与人物文件操作在预览／执行前检查源文件可读、源目录可移出、目标或最近的现存祖先目录可写。权限错误保留完整路径，不再展示为可执行。该检查不能代替执行时校验，外部权限变更仍可能导致操作失败。

归档使用 `operation_id` 绑定预览版本和所选视频；`GET /api/plan/progress?id=...` 查询对应阶段及最终回执。回执保存在 `FACES_BASE/archive-runs/`，最新进度仍写入 `jobs/archive.json`。页面提交当帧反馈，底栏显示真实阶段和数量；断线后查询回执，重复提交不会重复移动。复制或同步没有可测量的字节进度时不估算百分比。

Peach 归档在移动前核对源／目标账本，按 `canonical_name` 或小写 `normalized_name` 复用人物，歧义时停止。`_face_admin_archive_ops` 保存预留和提交状态；响应丢失后先查询事务状态，取消状态阻止迟到提交。只有确认账本未提交才回退文件；账本状态未知、本地提交失败或回退不完整时保留恢复写锁，不允许盲目重试。

NAS 的 `/mnt/mnt2/media` 使用 `root_squash,anonuid=1000,anongid=1000`。媒体服务目录由 `maintenance/media-directory-permissions.py` 配置 UID 1000 的访问和默认 ACL，范围仅为 `pikpak/creators`、`pikpak/My Telegram`、`pikpak/.face-cleanup-staging` 的目录；已有文件、属主和其他主体的有效权限保持不变。工具默认只读，`--apply --backup <媒体树外的新目录>` 才写入，原 ACL 可通过 `setfacl --restore=<backup>/before.acl` 回退。外部工具显式 chmod 或替换 ACL 仍可能破坏继承，应在导入端保持同一服务身份。

`tests/archive-ledger.test.mjs`、`tests/file-permissions.test.mjs`、`tests/http-archive-reliability.py` 和 `tests/test_media_directory_permissions.py` 覆盖名称规范化、事务回执、迟到请求、权限拦截及 ACL 有效权限保留。HTTP 测试仅使用明确标记的隔离夹具与专用端口。


### 后台分析与人物预览版本

SQLite 版本只纳入本次操作会改写的视频索引和任务：选中的视频 ID、源路径／目录，以及人物名或别名相关的候选资料。无关任务的阶段、重试次数、更新时间和无关视频索引变化不再使合并／删除预览失效；相关记录、文件指纹、JSON 资料与 Peach 账本的过期校验仍保留。

`tests/http-person-version.py` 在独立夹具中复现无关后台更新导致的误报，验证连续后台更新时可以合并，并确认相关视频索引、候选资料、账本及真实文件变化仍拦截旧确认。

## Rust 暂存与恢复

开启 `FILE_OPERATIONS_BACKEND=rust` 和 `FILE_OPERATIONS_ENABLE_RUST=1` 后，`delete-files` 与单文件 `restore-files` 使用同一原生执行器、写锁、逐文件步骤和完整范围补偿。删除保留相对子目录，移入 `.face-cleanup-staging/person-deletions/<操作编号>/<人物>/`，同名但不同目录的视频各自保留。暂存与恢复更新稳定编号的实际路径、本地 SQLite / JSON 和 Peach 路径；恢复到另一个明确人物时同步主归属。原始账号、规则和审核决定不会从旧备份自动恢复；只有实际恢复到人物目录才清除该人物的删除标记。

`GET /api/staging` 在 Rust 模式返回统计及每页最多 100 个真实文件（`rows`, `offset`, `next_offset`）；`GET /api/staging?id=<编号>` 查询原后端回执。`POST /api/staging` 支持 `preview/apply/reconcile`，请求为 `{action:"restore-files",person:"",files:[{vid,path,version}],target_person?,target_folder?}`；缺省目标只允许有可核对原位置的文件。指定人物可创建缺失目录，确认前展示完整目的路径；同名目标、晚到文件、来源或账本变化均阻止旧确认，绝不覆盖。

来源保存在事务快照中的 `staging-origins.json`，并能读取原生及旧 `person-operations` 已完成回执的精确路径映射。来源未知的历史文件显示未知，必须明确指定目标人物。旧回执保持原样。暂存列表不跟随符号链接，扫描错误返回错误，超过 100,000 个目录项拒绝单次扫描；这不是可安全永久清空的范围证明。

`/api/delete` 的旧直接移动入口已返回 410，应使用人物文件预览操作。永久删除和清空不属于此恢复接口；已追加的迁移票 #16 必须在最终切换前完成，且需合并 #6 重复件和整个人物删除的来源约定。其他暂存功能并行发布时仍须按其实际合同补充联合验证，不能把未验收的 Node/Python 实现作为原生回退。

隔离验收：`python3 tests/http-rust-staging.py --port 18987` 覆盖删除／恢复、未知与旧来源、相对目录同名保留、晚到冲突、本地及 Peach 故障、账本已提交的核对、SIGKILL 后恢复和稳定引用。`tests/http-rust-staging-gateway.py` 仅访问标记夹具 `/tmp/face-admin-person-fileops-staging-08` 的 Next `18986`，验证公开 API 和 Range 字节；其末尾保留一份样片供浏览器恢复验收。

Rust 整人物删除（#11）通过 `POST /api/persons/manage` 的 `delete-person` 预览／确认执行，沿用同一原生执行器及目录身份、逐文件回执和完整范围补偿。预览包含隐藏文件、附件、所有子目录与空目录；仅附件、空目录和仅有活动人物资料的情况也可处理。文件移入全局 `person-deletions/<操作编号>/<当前人物>/`，稳定编号和原始 OCR 保留；撤回该人物及其别名的活动队列、账号关联、模板、拒绝记录与识别映射，记录删除标记，历史归档不使人物重现。Peach 只同步目录资产路径，历史人物实体、别名、角色及关系保留。

新暂存来源保存原始路径和当时的当前人物名，后续别名解析只影响操作身份，不改写来源审计。恢复文件仍需独立确认，不恢复已撤回的账号和规则。确认提交后的源目录清理若遇到外部新文件，会保留该文件并返回清理警告；核心文件或存储状态无法核实时仍保留恢复锁。该软删除不调用永久删除流程。批量人物界面的原生调度由 #12 另行集成；不能将单项原生验收当作批量切换证明。

`tests/http-rust-person-delete.py` 验证整目录／空人物、活动与历史资料、外部变更、实际 SQLite 触发器故障、全部存储补偿及重启恢复。`tests/http-rust-person-delete-gateway.py --root <标记夹具>` 仅访问 Next `18992`，验证人物与别名隐藏、旧回执、暂存字节和稳定编号 Range；测试数据均为隔离夹具。
